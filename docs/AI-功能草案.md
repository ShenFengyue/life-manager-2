## 0. 前置：允许联网，但必须严格控制上传内容

现状：规则三是「完全本地、不使用远程 API、不发送数据至任何外部服务」。
要接 DeepSeek 就等于开一个口子。经确认，**允许联网，但按下面的红线执行**——
规则三相应改为：

> 默认完全本地；联网功能一律**默认关闭**，只在用户手动点击时发生，
> **每次都先告诉用户要发什么**，且可以整体关掉。

### 联网与隐私红线（硬性）

1. **默认关闭**：不填 API Key、不打开开关时，应用行为与现在完全一致，离线可用。
2. **每次联网前必须预览**：逐字显示"将要发送的内容"，用户点确认后才发送；取消则不发送。
3. **只允许发送这两类内容**：
   - 你这一次手动输入的那段文字；
   - 节点的**名称与归属路径**清单（包含 id，用于让模型选节点）。
4. **绝不允许发送**：整个数据库、活动记录的历史备注汇总、日记内容（`data/diary.md`）、
   备份文件、导出文件、`data/` 下任何文件的整体内容。
5. **Key 只存本机** `data/ai.json`（明文保存，页面上写明这一点），不写入日志。
6. **发送日志**：每次请求在 `data/logs/ai.log` 里记一条
   （时间、用途、发送字节数、成功/失败、错误摘要），**不记 Key、不记完整正文**。
7. **失败不影响数据**：网络失败、解析失败一律不写入任何数据；AI 结果必须先给人看过才落库。
8. 断网、没有 Key、关掉开关时，AI 相关按钮禁用，其它功能完全不受影响。

### 自动检查（实现时一并加）

- 源码白名单测试：除 `app/ai.py` 外，任何模块仍不得使用网络库。
- 单测构造 AI 请求体，断言其中**不含**：日记文本、活动记录全量、备份/导出路径、API Key 之外的密钥字段。
- 卸载测试：`data/ai.json` 不存在时，应用全部功能可用（等同离线）。

## 1. 功能一：一句话拆成多条记录

**解决什么**：你现在的痛点是"记一条要点好几下"。这个功能把它压成"说一句 + 确认"。

**交互**

1. 入口放在「记录地图」页面顶部，一个单行输入框：`今天背了单词，去健身房练了腿，晚上跟朋友聊了项目想法`。
2. 点「拆分」→ 弹窗里列出候选记录，每条一行：
   `[节点下拉框：领域 3 → 进程 3-3 → 线程 3-3-2] [备注文本，可改] [日期，默认今天] [删除该行]`
3. 底部按钮：`[全部写入] [取消]`。**不点"全部写入"就不会产生任何数据。**
4. 写入时逐条调用 `service.record_activity(node_id, note, date)`（沿用现有事务与快照规则），
   某条失败就报告是哪一条，已成功的保留。

**约束**

- AI **只能从现有节点里选**（给它「领域 → 进程 → 线程」的 id + 名称 + 路径清单），不允许新建节点；
- 匹配不上时该行节点留空，由你手动选；
- 日期默认今天，可在预览里改；一条最多一句话，不加标签、不加字段。

**离线降级**：没有 AI 时，同一个输入框提供"按标点拆成多行"，节点由你逐行选（带自动补全），
功能仍然可用，只是不自动猜节点。

## 2. 功能二：周 / 月复盘

**解决什么**：热力图告诉你"多不多"，复盘告诉你"偏没偏"。

**做法**

1. **统计一律在本地算好**（不依赖 AI）：窗口内总次数、按领域与进程的分布、有记录的天数、
   当前连续天数、哪些线程多久没动、置顶重点的"下一步行动"。
2. AI 只做一件事：把这些**数字**写成一段通顺的中文，并可选给出 2–3 条"下周建议"。
   → 发给模型的内容 = 上面那张数字表 + 节点名称路径，**不含活动备注原文**。
3. 结果保存到 `data/reviews/2026-W42.md`（Markdown，与日记同样的"一个文件一条记录"思路），
   在页面上可回看。

**离线降级**：没有 AI 时用**本地模板**生成同样结构的复盘（数字完全一致，只是文风朴素）：

> 本周 34 次活动，集中在 线程 3-3-2（9 次）和 线程 3-1-1（7 次）；进程 3-3 连续 6 天有记录；
> 线程 3-3-1 已 12 天没有任何进展。

## 3. 明确不做

- **不做**"下一步行动建议"（上一轮讨论里排第 3 的候选）：容易变成 AI 说教，价值最低。
- 不做自动写入：AI 的产出必须先经你确认。
- 不做云端同步、不做账号体系、不做把整库上传的"智能分析"。
- 不引入第三方 HTTP 依赖（用 Python 标准库实现请求）。

## 4. 技术方案（实现时参考）

| 模块 | 职责 |
| --- | --- |
| `app/ai.py` | DeepSeek 客户端（OpenAI 兼容的 `/chat/completions`，模型名可配，默认 `deepseek-chat`；超时、重试 1 次、错误可读）；唯一允许联网的模块 |
| `app/ai_tasks.py` | 构造提示词、解析结构化返回（要求返回 JSON）、本地校验（节点 id 必须存在） |
| `app/pages/ai.py` | 「AI」页面：Key 填写、开关、测试连接、每次发送前的内容预览、发送日志 |
| `data/ai.json` | Key 与开关（明文，页面写明） |
| `data/logs/ai.log` | 发送日志（时间 / 用途 / 字节数 / 结果，不含 Key 与正文） |

**返回格式**：要求模型只返回 JSON，例如
`[{"node_id": "…", "note": "…", "date": "2026-10-15"}]`；
解析失败就展示原始文本让你手动处理，**绝不猜着写入**。

**页面位置**：左栏最下方「数据」之上再加一项「AI」（默认关闭时该页只显示设置说明）。

## 5. 验收标准

1. 没配 Key 时，应用与现在完全一样（含离线可用）。
2. 一句话拆条：给出 3 段话 → 3 条候选，能落到 3 个不同线程；节点可在预览里改。
3. 复盘：生成的数字与本地统计逐项一致（抽查 3 项）。
4. 每次发送前都能看到"将要发送的内容"；点取消不发送、不写日志。
5. `data/logs/ai.log` 里能查到每次发送的时间与字节数，且**查不到 Key**。
6. 拔网线后：AI 按钮不可用，其它功能一切正常。
